Liaison covers a small business's sales, support, delivery and money in one place, with agents doing the routine work and people deciding. This page answers the questions people ask when they are choosing a tool. Where the answer is no, it says what to do instead. The examples use the sample company in the [demo](demo.md), Resonant Audio Labs, which you can open and try.

## Sales and customer relations

| Does it do… | Answer |
| --- | --- |
| A CRM? | Yes, a lean one: [companies](../sales/companies.md), [deals on a board](../sales/deals.md) and a timeline read from your other apps. There is no marketing suite. |
| Email sequences? | An agent drafts each follow-up and a person approves it, unless you decide otherwise. A reply, an opt-out or a closed deal stops it, checked at the moment of sending. There is no sequence editor. See [Follow up on quiet deals](../sales/follow-ups.md). |
| Open tracking? | No, and it is not built on purpose. A reply is the signal. |
| Lead scoring? | Your rule, applied by an agent and stored as tags or metadata. There is no built-in model. See [Rank your leads](../sales/lead-scoring.md). |
| Enrichment? | An agent reads public websites and proposes a record. No data vendor is included. See [Research prospects and draft replies](../sales/research-prospects.md). |
| Mass mail? | No. Mail is one-to-one. Use a marketing tool for broadcasts; [opt-outs](../sales/opt-outs.md) are still respected on every commercial mail Liaison sends. |
| Booking links? | No. An agent can find a time in your [calendar](../apps/calendar.md) and send the invite. |
| Reports and dashboards? | Ask an agent, or have a [routine](../agents/routines.md) send the answer. [Dashboards](../agents/dashboards.md) show figures an agent built, and Home shows what needs you. There is no report builder. See [Forecast your pipeline](../sales/forecast.md). |
| Proposals? | An agent drafts the text from past work; the priced part is a quote. See [Proposals](../sales/proposals.md). |

## Delivery, time and projects

| Does it do… | Answer |
| --- | --- |
| Time tracking? | Give a task a timebox, and whoever did it can say afterwards how long it took. Before billing, a person asks an agent to reconcile planned against real. There is no timer and no weekly grid. If a client needs dated hours, one switch on the project gives a timesheet from what people entered. Real time is optional, so a figure built on it says how complete it is. See [Time and budgets](../apps/projects.md#what-time-and-budgets-is-for). |
| Timesheets for payroll or labour law? | No. Dated hours are for clients. A project's sheet is not a working-time register. |
| Resource planning? | One page: planned timeboxes per person per week, and "who can take this?" in chat. There is no scheduler. See [Capacity](../apps/projects.md#read-capacity-and-set-days-off). |
| Monitoring staff? | No. Nothing is captured, no figure ranks a person, and a gap in entries means nothing. |
| Project budget and margin? | Yes, on the project: timebox, real, left, and invoiced minus time at cost for finance, marked partial when real time is incomplete. See [Read a project's budget](../apps/projects.md#read-a-projects-budget). |
| Client status reports? | A routine drafts the report from the project's tasks, a person approves it, and the client reads it in the portal. See [Send a client report](../apps/projects.md#send-a-client-report). |

## Money

| Does it do… | Answer |
| --- | --- |
| Quotes and invoices? | Yes. An agent drafts, a person approves, and the number is assigned at issue. See [Issue invoices and quotes](../apps/invoicing.md). |
| Recurring invoices, retainers? | Yes. A person approves each draft, and the number is assigned at issue. See [Recurring invoices](../apps/recurring.md). |
| Stripe? | Yes: customers, subscriptions, failed payments, monthly recurring revenue with its [rules stated](../money/mrr-rules.md), and refunds through approval. Liaison holds [no card data](../money/no-card-data.md). See [Connect Stripe](../apps/stripe.md). |
| Accounting? | No. Liaison issues invoices and connects to your accounting tool where one is supported, such as [Pennylane](../apps/pennylane.md). |
| Payroll, HR, expenses? | No. |

## Agreements and clients

| Does it do… | Answer |
| --- | --- |
| E-signature? | A simple signature, with evidence a third party can check offline. It states its level and is not a qualified signature, so check what your contract needs. See [Agreements](../apps/agreements.md). |
| A client portal? | Yes, a restricted one that shows only what you shared. Clients do not talk to agents there. See [Run a client portal](../apps/client-portal.md). |

## Not built, on purpose

These are decisions, not gaps in progress. Each one says what to do instead.

- **Live timers, productivity scores and activity timelines of a person.** Say afterwards how long it took.
- **Leave requests, balances and HR records.** Days off in Liaison only say "less time available". Keep an HR tool for the rest.
- **Booking pages, mass mail and a sequence builder.** Ask an agent to find a time, send one-to-one mail, and describe the steps in a routine.
- **Advanced or qualified signatures.** Use a provider where the law asks for more, then import the signed file (see [Import a contract signed before Liaison](../apps/agreements.md#import-a-contract-signed-before-liaison)).
- **Payment on the client portal.** Bank details sit on the invoice, and Stripe customers pay on Stripe's own pages.

## Check it yourself

The quickest test is to look. Open the [demo](demo.md) and ask its agent any question from the tables above, or [install Liaison](install.md) and try it on your own data. An agent answers from what Liaison can do today, and it does not promise anything else.
